# UAT: `compaction_summary_searchable` v1

## Intent

Verify that **compaction summaries** (not just the verbatim demoted
messages) make their way into the archive and are retrievable by
semantic / lexical search when the user asks about a topic discussed
many turns ago.

This pins the contract: `MemvidStoringCompactor` shadow-writes the
inner compactor's artifact and that artifact is indexable.

## Setup

- Token budget on `CompactingMemory` ≤ **1,500 tokens** so compaction
  is triggered at least twice during the script.
- Inner compactor: any deterministic summariser (e.g.
  `TemplateCompactor`) or an LLM-backed compactor — either is fine,
  as long as the summary mentions topic keywords.
- Fresh archive path.

## Script (run verbatim)

### Block 1 — the topic the user will probe later

```text
User: I'm planning a 3-week trip to Hokkaido in February. The main
draw is the Sapporo Snow Festival in the first week, followed by 5
days skiing at Niseko, and ending with onsen towns around Noboribetsu.
Budget is roughly 4500 USD excluding flights. Help me think about
this.
```

Then have **3 follow-up turns** drilling into Hokkaido logistics
(rail pass, ski gear rental, onsen etiquette). Each ≥ 80 words.

### Block 2 — totally unrelated long stretch

Send **20 filler turns** (≥ 80 words each) on unrelated topics. By
the end of this block, compaction should have fired at least once
and the Hokkaido messages should be out of the working set. Suggested
topics: Roman concrete, Kalman filters, mushroom foraging, Welsh
choral tradition, refrigeration cycles, Sumerian cuneiform, jazz
harmony, anodising aluminium, the Antikythera mechanism, FM
synthesis, urban planning of Brasília, marine chronometers,
beekeeping winter prep, Old Norse skaldic poetry, optical fibre
fabrication, the Boltzmann brain thought experiment, plate
tectonics, Hangul, watchmaking complications, and zero-emission
shipping fuels.

### Block 3 — the probe

```text
User: Earlier we were planning a trip somewhere cold. Where was that
and what was the main reason for going?
```

```text
User: What was the approximate budget I mentioned?
```

## Acceptance criteria

| # | Criterion                                                                 | Pass condition                                                                              |
| - | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1 | The topic is recovered                                                    | Block 3 Turn 1 reply names **Hokkaido** (substring) and references **Snow Festival**, **skiing**, or **onsen**. |
| 2 | The budget is recovered                                                   | Block 3 Turn 2 reply names **4500** (substring, with or without `USD`/`$`).                 |
| 3 | The recall comes from compacted memory, not the live window               | The Hokkaido block is well outside the configured token budget. Reply must not be a verbatim quote of the original user message; expect a paraphrased summary. |
| 4 | No invented details                                                       | Reply does not assert facts not in the original Block 1 (e.g. wrong cities, wrong duration). |

## Failure modes to log explicitly

- **F1** — Block 3 Turn 1 says "I don't recall any trip planning".
- **F2** — Reply names a different destination (Hokkaido replaced by, e.g.,
  "Iceland"); hallucination.
- **F3** — Reply names Hokkaido but invents a different budget.
- **F4** — Reply is a long verbatim quote of the original message
  (compaction didn't run; this is a working-window hit, not a summary
  retrieval) — still passes #1 but fails #3.

F1–F3 → `FAIL`. F4 alone → `INCONCLUSIVE` (rerun with smaller token
budget).
