# UAT: `scope_isolation` v1

## Intent

Verify that two conversations using **different memory scopes** do
not leak content into one another's retrieval results.

This pins the contract: the `scope` field on `MemoryConfig`
participates in retrieval filters, and a query under scope A cannot
surface frames written under scope B.

## Setup

- Two parallel conversations, each with its own scope label:
  - **Conversation X** — scope `project-aurora`.
  - **Conversation Y** — scope `project-vega`.
- Both conversations point at the **same archive path** (the test is
  pointless otherwise — scope only matters when storage is shared).
- Token budget low enough that demotion fires for both conversations.

## Script (run verbatim)

### Phase 1 — seed Conversation X (scope=`project-aurora`)

```text
User-X: For project Aurora: the deployment code-name is "Northern
Compass", the launch window is mid-March, and the lead engineer is
Priya Ramanathan.
```

Then 6 filler turns on Aurora-related made-up content (≥ 60 words
each) so the seed message is demoted.

### Phase 2 — seed Conversation Y (scope=`project-vega`)

```text
User-Y: For project Vega: the deployment code-name is "Southern
Cross", the launch window is late June, and the lead engineer is
Marcus Okafor.
```

Then 6 filler turns on Vega-related made-up content (≥ 60 words
each) so the seed message is demoted.

### Phase 3 — probe each scope independently

In **Conversation X** (scope `project-aurora`), the user asks:

```text
What was the deployment code-name and who's the lead engineer?
```

In **Conversation Y** (scope `project-vega`), the user asks:

```text
What was the deployment code-name and who's the lead engineer?
```

Run both probes within the same process and within the same archive,
but in their original scope contexts.

## Acceptance criteria

| # | Criterion                                                                  | Pass condition                                                                                                  |
| - | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 1 | Conversation X answers about Aurora only                                   | X-reply names **Northern Compass** and **Priya Ramanathan**, and does **not** mention "Southern Cross" or "Marcus Okafor". |
| 2 | Conversation Y answers about Vega only                                     | Y-reply names **Southern Cross** and **Marcus Okafor**, and does **not** mention "Northern Compass" or "Priya Ramanathan". |
| 3 | Cross-scope leakage is absent in retrieved context                         | If the agent surfaces its retrieved chunks, none of X's retrieved chunks are tagged with Y's scope or vice versa. |

## Failure modes to log explicitly

- **F1** — X-reply names Marcus / Southern Cross (Vega-side facts).
- **F2** — Y-reply names Priya / Northern Compass (Aurora-side facts).
- **F3** — Either reply mixes both code-names ("Northern Cross", "Southern Compass") — hallucinated blend.
- **F4** — Either reply says "I don't recall".

F1–F3 → `FAIL`. F4 alone in **one** scope → `INCONCLUSIVE` (demotion
may not have fired); F4 in **both** scopes → `FAIL`.
