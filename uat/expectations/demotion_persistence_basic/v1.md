# UAT: `demotion_persistence_basic` v1

## Intent

Verify that a fact mentioned by the user **before** the agent's
working-set window evicts it is still recallable from the underlying
archive after a long stretch of unrelated conversation.

This pins the contract: demoted user messages persist into `.mv2` and
remain retrievable via retrieval-augmented recall, even after they
leave the in-memory chat history.

## Setup

- Token budget on `CompactingMemory` ≤ **2,000 tokens** so demotion
  fires within ~10 turns of moderate-length filler.
- Archive at a fresh path (delete any existing `.mv2` before run).
- No system preamble that hard-codes the secret fact.

## Script (run verbatim)

### Turn 1 — user

```text
I want to tell you something I'll quiz you on later: my favourite
coffee shop in Lisbon is called "Hello, Kristof" and it's on
Rua do Poço dos Negros. Got it?
```

### Turn 2 — user

```text
Acknowledge that you've recorded it, then let's change topic
completely.
```

### Turns 3–14 — user

Send **12 unrelated filler turns**, each at least 80 words, on topics
that share no vocabulary with the fact above. Suggested topics:
container orchestration, the history of the Bayeux Tapestry, Bach's
keyboard partitas, ocean thermohaline circulation, the etymology of
"sabotage", commuter rail signalling, paper-making, the Voynich
manuscript, lichen biology, traffic-light timing algorithms, the
Tunguska event, and zero-knowledge proof systems.

Do not let the assistant steer back to Lisbon, coffee, or the
quiz. If it tries, acknowledge briefly and continue with the next
filler topic.

### Turn 15 — user (the probe)

```text
Quiz time. What's the name of my favourite coffee shop and what
street is it on?
```

## Acceptance criteria

| # | Criterion                                                          | Pass condition                                                                                                 |
| - | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 1 | The fact survives eviction                                         | Turn 15 reply names **"Hello, Kristof"** (case-insensitive substring match) **and** **"Rua do Poço dos Negros"** (street name; diacritic-insensitive match acceptable). |
| 2 | No hallucinated substitution                                       | Reply does not invent a different shop name or street. If unsure, the assistant must say so rather than guess. |
| 3 | The recall is anchored in the user's earlier turn, not the prompt  | Turn 15 user message intentionally omits both the shop name and street. The assistant must reconstruct them from memory, not echo them.  |
| 4 | No duplication of the same fact across multiple retrieved chunks   | If the assistant cites retrieved context, the same fact should appear once, not multiple near-identical times. |

## Failure modes to log explicitly

- **F1** — Assistant says "I don't have that information" / "I can't recall".
- **F2** — Assistant invents a plausible but wrong shop name (hallucination).
- **F3** — Assistant returns the right shop name but wrong street, or vice versa.
- **F4** — Assistant returns the fact but also returns 3+ duplicated copies of the same memory.

Any of F1–F4 → `FAIL`.
